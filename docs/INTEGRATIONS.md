# Integration contracts

## Status

AirBoard (`D:\airboard\airboard`) and GestureLink (`D:\gesture link`) were inspected. Both are standalone, local-first browser apps. Neither currently exposes a server, WebSocket endpoint, extension API or command protocol. **Meridian does not claim a live integration with either one.** All Meridian core features work without them.

This document defines the minimal contract both projects would need to implement. It is intentionally small and local.

## Transport

A local, explicit pairing between two browser contexts on the same device:

- `window.postMessage` between same-origin framed contexts, **or** a localhost WebSocket on a port chosen by the companion app.
- No camera frames, no study records and no credentials are sent in commands.
- A random pairing token is generated by Meridian and stored only in `db.meta` / the companion's local settings.

## Handshake

1. Companion announces: `{ type: 'meridian.hello', protocol: 1, name, capabilities: string[] }`.
2. Meridian replies: `{ type: 'meridian.ack', protocol: 1, token, capabilities: ['focus.start','focus.pause','focus.resume','task.next','task.previous','nav.today','nav.plan','nav.review','notes.open','dialog.dismiss'] }`.
3. Companion sends commands with the token. Meridian validates origin + token + capability before acting.
4. Capabilities and version are renegotiated on every connect. A connection expires after 12 hours and can be disconnected from Settings → Devices.

Example command:

```json
{
  "type": "meridian.command",
  "protocol": 1,
  "token": "<local token>",
  "id": "cmd-42",
  "action": "focus.start",
  "args": { "minutes": 25 }
}
```

Meridian replies with `{ type: 'meridian.result', id, ok: true }` or `{ ok: false, error }`. Recognition stays entirely in GestureLink/AirBoard; Meridian only accepts approved events and never opens a camera.

## AirBoard display channel (future)

If AirBoard implements the handshake, Meridian can publish a read-only snapshot on request:

```json
{
  "type": "meridian.snapshot",
  "protocol": 1,
  "token": "...",
  "payload": {
    "session": { "running": true, "remainingSeconds": 1200, "course": "Organic Chemistry", "chapter": "Aromaticity" },
    "today": { "focusMinutes": 95, "nextAction": "Revise Orthogonality", "revisionDue": 3 },
    "week": [{ "day": "2026-11-24", "minutes": 120 }]
  }
}
```

Aggregate study data only. No private notes.

## What is required before enabling a UI

1. A real companion implementation of the handshake above.
2. An end-to-end test with that companion against a local instance.
3. A Settings → Devices entry showing connection status, identity, capabilities, version, expiry and disconnect.

Until all three exist, the integration remains documented only. No decorative connection control is shipped.
